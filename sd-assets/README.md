# SD assets — mock parts catalog + QR codes

Generated by `scripts/gen_mock_qr.py` (run with the scripts venv:
`scripts/.venv/bin/python scripts/gen_mock_qr.py`).

| File | Goes where | Purpose |
|------|------------|---------|
| `parts.json` | SD card root → `/sdcard/parts.json` | QR-label → part map the HMI Load screen looks up |
| `qr/MOCK-PART-#####.png` | print / display | one scannable QR per part |
| `qr/contact-sheet.png` | print | all codes on one labelled sheet |

## How it's wired

1. The QR payload is exactly the label, e.g. `MOCK-PART-00001`.
2. At boot the HMI reads `/sdcard/parts.json` into `parts_catalog`
   (`esp32-hmi/src/storage/parts_catalog.cpp`).
3. On the **Load** screen the scanner free-runs at 5 Hz. The first
   recognised code latches in as the part and the UI shows it with
   **Place reel / Rescan / Cancel**. Further scans are ignored until
   **Rescan** is pressed. Unknown codes show an "Unrecognised code"
   status. If no scanner/catalog is present, **Simulate scan** picks a
   random catalog part instead.

## Deploying parts.json to the card

`scripts/deploy-sd.sh` copies `sd-assets/parts.json` to the card root
alongside the firmware images. Or copy it by hand to the SD root.

To change the catalog, edit the `PARTS` list in `scripts/gen_mock_qr.py`
and re-run it; the part `id`/`name`/`pkg`/`mfg` mirror the built-in
`kCatalog` in `esp32-hmi/src/ui/app_state.cpp` so scanned parts line up
with rack contents.
