# mock-inventree

A FastAPI service that mocks the **SmartReel InvenTree plugin** HTTP API. The
HMI talks to this server during development so we can iterate on the
HMI<->plugin contract without standing up real InvenTree. The real plugin will
later implement the same contract by calling InvenTree internally.

The API is **purpose-built for the HMI's workflows** (resolve / assign / pick /
pickjobs / anomaly), not a thin proxy of InvenTree's REST. That keeps the HMI
simple; the plugin does the translation.

## Quick start

```sh
cd debug-fw/mock-inventree
./setup.sh           # creates .venv, installs deps, generates TLS cert (one-off)
./run.sh             # starts on https://0.0.0.0:8443, token "dev-token"
# in another shell:
curl --cacert certs/server.crt \
     -H 'Authorization: Token dev-token' \
     https://localhost:8443/api/v1/health
# or, during dev, skip cert verification with -k:
curl -k -H 'Authorization: Token dev-token' https://localhost:8443/api/v1/health
```

- Status dashboard at <https://localhost:8443/> (auto-redirects to `/ui/`).
- Auto-generated Swagger UI at <https://localhost:8443/docs>.

### Status dashboard

Open `https://<server-host>:8443/` from any browser on the same network -- the
page polls `/api/v1/{health, rack, pickjobs, _dev/anomalies, _dev/ops}` every
2 s and renders the rack as a 4 x 16 grid (click a slot to inspect contents),
plus per-job progress and an anomaly log. The token is read from the input
field at the top and cached in browser localStorage. `/health` is unauth'd so
the heartbeat works even before a token is set.

First time on a new browser: visit the URL, accept the self-signed cert
warning, paste the token, hit Save. Subsequent visits skip both steps.

To reach the dashboard from another machine, look up the server's LAN IP
(e.g. `ip -4 addr | grep inet`) and visit `https://<lan-ip>:8443/`. The cert
generated by `gen-cert.sh` already includes the LAN IP detected at setup
time as a SAN, so cert verification just works -- but most browsers will
still flag self-signed roots; click through the warning once.

### TLS

`./gen-cert.sh` writes a self-signed cert to `certs/server.{crt,key}`. SANs
cover `localhost`, the machine hostname, `127.0.0.1`, `::1`, and the first
non-loopback LAN IPv4 if one is detectable. Valid 825 days; `setup.sh` calls
`gen-cert.sh` and the script no-ops if a valid cert is already in place.

Force a fresh cert: `rm -rf certs/ && ./gen-cert.sh`.

The cert's SHA-256 fingerprint is printed at generation time -- the HMI
client can pin that string instead of installing the cert as a CA. To set
the HMI to skip verification entirely during dev, that's a client-side
config knob (the server doesn't care).

To opt out of TLS during dev: `SR_HTTPS=0 ./run.sh` -> plain HTTP on `:8000`.

### Env vars (all optional)

| Var | Default | Meaning |
|---|---|---|
| `SR_TOKEN` | `dev-token` | required in `Authorization: Token <...>` |
| `SR_HTTPS` | `1`        | `0` to serve plain HTTP |
| `SR_PORT`  | `8443` (https) / `8000` (http) | listen port |
| `SR_HOST`  | `0.0.0.0`  | listen address |
| `SR_RACK_LOCATION_ID` | `42` | InvenTree location id the rack registers as |
| `SR_LATENCY_MS` | `0` | inject artificial per-request latency for testing |

## Data model (mock-side)

- **Part**  - catalog entry (`R-10K-0805`, "RES 10kohm 1% 0805", `0805`, Yageo).
- **StockItem**  - a specific reel: id, part, qty, batch, barcode, location_id.
  The thing you actually scan.
- **Location ids** - `42` is the rack; `4201..` are slots underneath it;
  `99` is Staging (picked reels land there); `98` is "pulled / unsorted"
  (anomaly clears land there).
- **PickJob**  - a list of parts to pick (one reel per item). Status is
  derived: pending / partial / done.
- **Anomaly**  - reconciliation event the HMI pushes when its sensors detect
  un-scanned activity.

## API contract  (`/api/v1`)

The contract is specified in **`docs/hmi-plugin-api.md`** (repo root) — that
file is canonical for both this mock and the real plugin in
`inventree-plugin/`. Don't change shapes here without updating it.

Headline semantics (rewritten 2026-06-11 per `docs/user-stories.md`):

- **Picks are whole-reel transfers.** `POST /rack/slots/{n}/pick` takes no
  qty; the slot's StockItem moves to Staging (or `destination_id`) and the
  slot is freed. The old qty-decrement / "Picked bin" model is gone.
- **Pick jobs** come from build orders. One item = one part; picking any
  reel of that part satisfies the item. Job `status` is derived
  (`pending`/`partial`/`done`); there is no cancel endpoint — HMI cancel is
  local and the job stays resumable.
- **`GET /rack`** doubles as the reconciliation source: logically-empty but
  physically-occupied slots mean stock was moved in InvenTree behind our
  back; the HMI lights those slots for manual removal.
- **`GET /_dev/provision`** returns the `SRPROV1:` payload + QR SVG used to
  provision the HMI without typing (dashboard → "Show setup QR").

Run `./smoke-test.sh` after contract changes — it exercises every endpoint
against a throwaway instance.

    routes/          # one file per resource group
