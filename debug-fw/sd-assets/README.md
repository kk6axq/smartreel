# Mock QR codes (bench test fixtures)

Generated by `scripts/gen_mock_qr.py` (run with the scripts venv:
`scripts/.venv/bin/python scripts/gen_mock_qr.py`).

| File | Goes where | Purpose |
|------|------------|---------|
| `qr/MOCK-PART-#####.png` | print / display | one scannable QR per mock part |
| `qr/contact-sheet.png` | print | all codes on one labelled sheet |

## How it's wired

1. The QR payload is exactly the label, e.g. `MOCK-PART-00001`.
2. On the **Load** screen the scanner free-runs at 5 Hz. The first
   recognised code latches in as the part and the UI shows it with
   **Place reel / Rescan / Cancel**.
3. The HMI resolves the scanned code over InvenTree (`resolve_barcode`);
   there is no SD parts catalog anymore. The mock server's `seed.py` has
   eight matching stock items, so these codes exercise the full
   scan → resolve flow on the bench.

To change the set, edit the `PARTS` list in `scripts/gen_mock_qr.py` and
re-run it; the part `id`/`name`/`pkg`/`mfg` mirror the built-in `kCatalog`
in `esp32-hmi/src/ui/app_state.cpp` and the mock seed so scanned parts
line up with rack contents.
